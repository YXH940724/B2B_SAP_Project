# 多销售范围订单体验设计

## 目标

将客户门户升级为可在多个客户销售范围内浏览、加购和结算的 B2B 订货体验，并提升商品、订单录入和订单详情的结构化展示质量。

## 范围与约束

- 销售范围只从当前登录客户在 SAP 客户主数据中维护的 `SalesOrganization`、`DistributionChannel`、`Division` 读取；浏览器传入的范围必须继续由服务端校验。
- 目录、购物车、结算和订单中心统一使用完整销售范围，而非只使用销售组织。
- 切换销售范围不清空购物车。每个购物车行保存其加入时的完整销售范围。
- 结算按完整销售范围分组，形成独立的订单预览与 SAP 创建请求；不同销售范围不得混在同一 SAP 销售订单中。
- 销售订单查询与详情仍仅返回当前登录客户的数据。
- 不新增对 SAP 的写权限；既有 `SAP_WRITE_ENABLED`、服务端重算价格与确认流程继续生效。

## 交互设计

### 销售范围

顶部范围选择器显示 `销售组织 / 分销渠道 / 产品组`。目录与订单中心共享该选择器的完整范围值；无销售范围时清楚显示 SAP 未维护提示，不发起不带范围的目录或订单查询。

### 商品目录与购物车

商品卡片显示物料号、物料描述、物料组、销售单位、价格、币种和销售范围。缺失描述统一显示“SAP 未维护描述”。购物车行展示同一销售范围标签，便于用户理解后续拆单。

### SAP 风格订单录入

从购物车结算进入独立订单录入页面。每个销售范围形成一个订单组：

- 表头：售达方、完整销售范围、订单类型、客户采购订单号、期望交货日期、备注。
- 行项目：物料号、物料描述、数量、单位、单价、币种、行金额和销售范围。
- 提交前：展示每组订单的行数、金额与将创建的 SAP 订单数量。

### 订单中心与订单详情

订单中心筛选器按完整销售范围筛选。订单详情使用三段式结构：状态与金额摘要、订单表头与业务伙伴信息、行项目与币种金额汇总。展示订单类型、客户 PO、完整销售范围、整体/交货/开票状态；SAP 未返回的字段显示“SAP 未维护”。

## 服务端数据与接口

- `GET /api/sales-areas` 保持为当前客户销售范围的唯一来源。
- 商品目录、购物车重新报价和预览/创建请求均传递并校验完整范围。
- 订单历史查询参数与服务模型扩展为销售组织、分销渠道、产品组的联合筛选，并保留分页与当前客户边界。
- 每条预览/创建订单只包含同一销售范围的行；返回结果按范围保留成功、失败和 SAP 订单号，避免一组失败掩盖其他组结果。

## 错误处理

- 范围不属于当前客户时返回既有服务端校验错误，前端显示可理解的提示并保留购物车。
- 某个订单组的 SAP 创建失败时显示该组错误及可重试动作，不重复提交已成功创建的组。
- 订单详情读取失败保持当前错误卡片，不用空白页面替代。

## 验收与测试

- 多销售范围客户能在目录和订单中心看到完整的范围选项，并按完整范围筛选。
- 切换范围后购物车行仍在，且带有原范围标签；结算预览按范围拆组。
- 商品、录入、订单详情页面均展示物料描述与结构化字段。
- 单元测试覆盖完整销售范围过滤、分组结算和当前客户边界；Playwright 覆盖范围切换、商品描述、订单详情结构与拆组预览。
