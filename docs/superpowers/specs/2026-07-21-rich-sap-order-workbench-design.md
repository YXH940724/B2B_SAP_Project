# SAP 客户订单工作台设计

## 目标

将订单中心从简要订单列表升级为面向客户的订单工作台。页面在同一工作区内提供订单抬头列表、经营分析和按需加载的订单详情，同时保证任何查询只能读取当前登录客户的 SAP 销售订单。

## 范围

- 默认显示当前客户最近 12 个月的 SAP 销售订单，服务端分页，每页 20 条。
- 列表展示订单号、创建日期、订单类型、客户采购订单号、销售范围、交货/开票/整体状态、净额和币种。
- 支持日期范围、销售组织、整体状态、交货状态、订单号和客户采购订单号筛选，并支持日期与金额排序。
- 点击订单行后按需读取订单抬头和行项目，在右侧详情抽屉展示业务信息。
- 订单分析包含订单数、净额、履约中订单、平均订单额、月度趋势、状态分布、销售组织金额排行、最高金额订单和最近下单日期。

## 非目标

- 不创建、更新或取消 SAP 订单。
- 不在门户数据库保存订单副本；SAP 是订单唯一事实来源。
- 不允许浏览器提供或覆盖客户号。

## 后端设计

`OrderHistoryService` 接收由会话解析出的客户号，并以规范化后的十位客户号查询 `A_SalesOrder`。服务端追加日期、状态、销售组织和关键词过滤，计算分析数据后返回分页结果。返回前再次校验每一行的 `SoldToParty`，防止 SAP 响应或浏览器参数造成跨客户泄露。

订单详情端点按订单号读取销售订单抬头和行项目。端点首先读取会话客户对应的订单列表或以订单抬头中的 `SoldToParty` 复核归属；不匹配时返回 404，不向浏览器透露订单是否属于其他客户。详情只在用户点击某行后调用。

状态码映射在服务端完成，返回结构同时保留原始码和中文显示文本。SAP 不返回、未维护或无授权的可选字段统一表示为 `null`，由前端显示“SAP 未维护”。

## 前端设计

订单中心自上而下包含：

1. 四张关键指标卡：订单总数、净额、履约中订单、平均订单额。
2. 月度订单趋势与状态分布。
3. 筛选栏和分页订单列表。
4. 订单详情抽屉：订单抬头、销售范围、客户采购订单号、收货/交付与开票状态，以及行项目表格。
5. 业务洞察：销售组织金额排行、最高金额订单、最近下单日期和状态提醒。

列表保持可用，即使详情读取失败；详情抽屉显示可重试的错误信息。加载期间采用明确的加载状态，空结果展示针对筛选条件的说明。

## 错误与安全策略

- 只读查询失败时返回明确、脱敏的 SAP OData 错误；不返回账号、密码、Cookie、完整 SAP 原始错误体或其他客户数据。
- 各模块独立失败：看板、列表、详情分别显示自己的错误或空状态。
- API 从 Cookie 会话读取客户号；忽略 URL、请求体或前端状态中的客户标识。
- 测试环境可以使用显式 TLS 配置；生产环境继续要求受信任的企业 CA。

## 验证方案

- 单元测试：客户隔离、筛选、排序、分页、状态映射、金额和趋势/排行聚合、详情归属校验。
- 路由测试：未登录拒绝访问；登录客户只能读取自身订单与详情。
- 浏览器测试：订单中心切换、筛选、分页、空状态、加载错误、详情抽屉打开及行项目渲染。
- 集成自测：在测试 SAP 中以客户 `100001` 验证订单查询与聚合，仅汇报统计结果，不输出订单明细。
