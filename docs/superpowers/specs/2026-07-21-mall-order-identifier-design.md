# 商城订单唯一标识设计

## 目标

为每笔商城提交生成可读且唯一的订单标识，将其写入 SAP 销售订单抬头字段 `PurchaseOrderByShipToParty`，并在商城中以该标识追踪、回查和展示对应的 SAP 销售订单号。

## 标识与拆单规则

- 商城母单号格式：`MALL-YYYYMMDD-XXXXXXXX`，其中后缀为八位大写十六进制随机值。
- 单一销售范围仅生成一个 SAP 子订单，子单号等于母单号加 `-01`。
- 多销售范围按既有规则拆分多个 SAP 子订单，子单号依次为 `-01`、`-02` 等。
- 每个子单号必须唯一，且只对应一个 SAP 销售订单；SAP 抬头的 `PurchaseOrderByShipToParty` 保存该子单号。

## 持久化模型

在现有 SQLite 数据库增加商城订单主表与子单表。

- 主表保存母单号、客户号、状态、创建时间和更新时间。
- 子单表保存子单号、母单号、完整销售范围、SAP 销售订单号、状态、请求摘要和失败原因。
- 子单号设为主键；`(母单号, 销售范围)` 设为唯一约束。
- 状态为 `PENDING`、`SUBMITTING`、`SUBMITTED` 或 `FAILED`。

## 提交流程

1. 用户在确认弹窗确认同步后，服务端按销售范围生成商城母单和子单记录。
2. 服务端在事务中保存 `PENDING` 子单，再将其更新为 `SUBMITTING`。
3. 创建 SAP 销售订单时，子单号写入 `PurchaseOrderByShipToParty`；客户、销售范围、条款和行项目继续使用已校验的提交数据。
4. SAP 返回销售订单号后，子单状态更新为 `SUBMITTED` 并保存 SAP 订单号。
5. 请求超时或响应缺失时，服务端先以子单号过滤 `PurchaseOrderByShipToParty` 查询 SAP；找到订单即回填并标记 `SUBMITTED`，未找到才标记 `FAILED`。
6. 同一商城订单再次提交时，已提交子单直接返回保存的 SAP 订单号，不重复调用 SAP 创建接口。

## 查询与界面

- 订单确认弹窗展示商城母单号和待创建的子单号。
- 创建结果展示每个销售范围的商城子单号、SAP 销售订单号和状态。
- 订单中心增加商城订单号列与搜索项。
- 订单中心合并 SAP 订单抬头与本地子单记录；商城订单号精确查询使用 SAP 的 `PurchaseOrderByShipToParty`。
- 订单详情和打印预览同时展示商城订单号与 SAP 销售订单号。

## 错误与安全

- 只有已登录客户可读取和提交自己的商城订单。
- SAP 创建继续需要写开关及用户确认；商城订单号不泄露 SAP 凭据或 CSRF 信息。
- 单个销售范围失败不影响其他范围的结果，但商城母单整体显示为部分失败，并可安全重试失败子单。

## 验证

- 验证编号格式、同日并发生成唯一性与多销售范围子单序号。
- 验证 SAP payload 使用 `PurchaseOrderByShipToParty`。
- 验证重复提交不重复创建、响应丢失时按商城子单号回查并回填。
- 验证订单中心、订单详情和创建结果正确显示商城订单号及 SAP 订单号。
