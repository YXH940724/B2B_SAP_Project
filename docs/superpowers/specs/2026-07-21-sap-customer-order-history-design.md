# SAP 客户订单查询设计

## 目标

订单中心以 SAP 为唯一订单数据源。当前门户登录客户只能读取其自身的 SAP 销售订单，并展示最近 12 个月的订单列表与汇总分析。

## 范围

- 不新增 SQLite 订单表，不将订单摘要写入本地或外部数据库。
- 不区分“门户同步订单”和“SAP 历史订单”；门户创建成功的订单会在下一次 SAP 查询时作为该客户的 SAP 订单出现。
- 门户服务端根据会话中的客户号构造 OData `$filter`；浏览器不得传入或覆盖客户号。
- 查询限定为最近 12 个月，并按创建日期倒序读取，最大 200 条。
- 保留现有 SAP 创建订单能力及其写入开关；订单中心查询本身只执行 GET。

## OData 查询

订单服务使用 `SAP_ODATA_BASE_URL` 指向的 SAP Sales Order OData 服务，并调用：

```text
GET /A_SalesOrder
  ?$filter=SoldToParty eq '<当前会话客户号>'
  &$orderby=CreationDate desc
  &$top=200
```

服务端把客户号规范化为十位 SAP 格式。对于 SAP 返回的订单，保留订单号、创建日期、销售组织、净额、币种与整体销售处理状态；在服务端再次过滤最近 12 个月，避免依赖不同 SAP 系统对日期过滤语法的差异。

## 组件边界

- `src/order-history.ts`：只负责读取和规范化 SAP 销售订单，以及生成近 12 个月的仪表盘数据；删除内存门户订单集合及写入方法。
- `src/portal-app.ts`：`/api/orders/history` 从当前会话获得客户号并调用订单查询服务；SAP 创建订单成功后不再记录本地门户订单。
- `src/web-server.ts`：构造只读订单查询服务，无需共享或新增数据库连接。
- `public/index.html` 与 `public/app.js`：订单中心只展示一个“SAP 销售订单”列表和汇总卡片。

## 数据流与失败处理

1. 客户登录，服务端建立绑定十位客户号的会话。
2. 客户打开订单中心，浏览器调用 `/api/orders/history`，不携带客户号。
3. 服务端从会话读取客户号，使用它查询 SAP `/A_SalesOrder`。
4. SAP 返回失败时，接口返回经过现有 SAP 错误映射后的错误信息；页面保留错误提示，不展示其他客户或缓存订单。

## 验收与测试

- 测试验证 OData `$filter` 仅使用会话客户号且补零为十位。
- 测试验证 SAP 返回的其他客户订单不会进入响应。
- 测试验证最近 12 个月汇总仅由 SAP 订单计算。
- 测试验证订单中心界面不再包含“门户同步订单”区块。
- 运行完整 `npm test` 与 `npm run build`。
