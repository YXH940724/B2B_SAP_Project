# 销售范围定价与拆分销售订单设计

## 目标

将客户商城从“仅按物料查询 A305/ZR01 价格”升级为以 SAP 客户销售范围为业务边界的订购门户。登录客户只能看到其当前销售范围内的可售物料；购物车可跨销售范围保存，结算时必须按销售范围拆分为独立的 SAP 销售订单。

销售范围的唯一键为：

`SalesOrganization / DistributionChannel / OrganizationDivision`

例如：`1000 / 10 / 00`。同一销售组织但渠道或产品组不同，仍是不同销售范围和不同 SAP 订单。

## 销售范围解析

1. 登录后，服务端使用已规范化的 10 位客户号读取 SAP 客户销售范围主数据。
2. 每个返回销售范围都包含销售组织、分销渠道和产品组；前端在顶部固定位置展示切换器。
3. 默认选择 SAP 返回的第一个销售范围，按三个字段的字典序稳定排序。
4. 客户没有销售范围时，门户显示“客户未维护销售范围，暂无法订购”，不请求商品目录。
5. 切换销售范围会刷新目录、物料组、搜索结果和分页；已经加入购物车的其他范围商品保留，不清空。

## 客户与销售范围定价

目录接口接受当前会话客户号与一个销售范围键，客户端不能任意指定其他客户号。服务端根据真实 SAP OData 元数据确认 A305 条件记录中客户及销售范围字段的位置，再构造仅服务端可见的精确过滤条件。

可售物料必须同时满足：

- 条件类型为 `ZR01`；
- 条件表为 `305`（A305）；
- 条件记录未删除、金额为正且处于有效期；
- 条件记录客户等于当前登录客户；
- 条件记录销售组织、分销渠道和产品组等于当前销售范围；
- 对应物料主数据可读取。

同一物料有多条匹配条件记录时，选择有效期开始日期最新的记录；仍无法唯一确定时不展示该物料，并记录不含敏感数据的服务端诊断日志。订单预览和创建时使用相同规则重新定价，绝不信任浏览器提交的单价。

## 购物车与拆单

购物车项目新增不可变的 `salesArea` 字段。用户可以先在 `1000/10/00` 加购，再切换到 `2000/10/00` 加购；右侧购物车按销售范围分节展示数量和金额。

结算预览把项目按销售范围分组，每组显示独立订单抬头、行项目、金额、期望交货日期、客户采购订单号和备注。确认后服务端顺序提交每个分组：

- 每个组使用其自身的销售组织、分销渠道和产品组创建 SAP 销售订单；
- 成功组返回 SAP 销售订单号并标记完成；
- 失败组保留明细和安全错误信息，可单独重试；
- 后续组仍继续提交，不回滚已成功的 SAP 订单；
- 默认不自动重试任何 SAP 写请求。

## 幂等与状态

增加持久化的门户提交组记录，至少保存随机提交组标识、客户号、销售范围键、项目指纹、状态、SAP 销售订单号、失败摘要及时间戳。密码、SAP 凭据和原始备注不写入诊断日志。

相同提交组再次请求时：

- 已成功组直接返回已创建的 SAP 订单号，不再次 POST；
- 进行中组返回“正在处理”，不并发写入；
- 失败组仅在客户显式点击“重试该销售范围”后创建新的提交尝试；
- 购物车变更项目、数量、销售范围或结算字段会形成新的组指纹。

该机制减少网络超时或刷新页面造成的重复订单风险，但不替代 SAP 侧的正式幂等键或业务审批。

## 页面与接口

- `GET /api/sales-areas`：返回当前登录客户可用的销售范围；不返回客户邮箱或 SAP 连接信息。
- `GET /api/catalog?salesOrganization=&distributionChannel=&division=&...`：仅返回当前会话客户、当前销售范围的有效价格物料。
- `POST /api/orders/preview`：接收带销售范围的购物车，按范围返回独立订单预览和重新定价结果。
- `POST /api/orders/submit`：在二次确认及 `SAP_WRITE_ENABLED=true` 下提交每个范围的未成功组并返回逐组结果。
- `POST /api/orders/retry/:submissionGroupId`：只允许当前客户对先前失败的同一销售范围组显式重试。

顶部销售范围切换器采用已确认的布局 A。右侧购物车按范围分组，结算页逐组显示状态；无有效价格、未维护销售范围、销售范围不匹配和部分提交失败均提供清晰的中文提示。

## 验证与边界

1. 使用 SAP `$metadata` 和只读样例请求验证客户销售范围实体及 A305 价格字段，禁止在该验证中发起 SAP 写请求。
2. 单元测试覆盖销售范围解析、客户/范围条件过滤、空销售范围、无价格、同物料多条件记录和分页。
3. HTTP 测试覆盖会话隔离、销售范围参数校验、跨范围购物车预览、逐组部分成功和失败组重试。
4. 订单负载测试验证每组使用自己的销售组织、分销渠道和产品组；写入开关未开启时不得调用 SAP POST。
5. 浏览器测试覆盖顶部切换器、分组购物车、逐组预览和结果展示。

现有注册、登录、验证码和销售订单写入防护必须保持有效。该设计不允许客户端自行切换客户号，也不允许通过页面绕过服务端 `SAP_WRITE_ENABLED` 与二次确认。
